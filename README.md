# 九宫数独精确覆盖求解与唯一性核验后端

纯本地、离线运行的经典 9×9 数独求解服务：TypeScript + Node.js + SQLite（Node 内置 `node:sqlite`，零原生依赖、零运行时第三方依赖）。只提供 HTTP API 与 CLI，无界面、无联网题库、无对角线/杀手笼等变体规则。

## 快速开始

```powershell
npm install        # 仅安装 typescript 与 @types/node（开发依赖）
npm run build      # 编译到 dist/
npm test           # 构建并运行全部测试（16 个）
npm run demo       # 内置演示：唯一解 / 直接冲突 / 无解 / 空盘多解 / 预算耗尽
npm start          # 启动 API 服务（默认端口 0 = 自动选空闲端口）
```

CLI 直接使用：

```powershell
node dist/src/cli.js solve 530070000600195000098000060800060003400803001700020006060000280000419005000080079
node dist/src/cli.js verify <题面> <答案>
node dist/src/cli.js check <题面>
node dist/src/cli.js serve --port 8080
```

题面为 81 字符或 9 行字符串，`0` 或 `.` 表示空格。

## 精确覆盖映射（Algorithm X）

每个候选落子 `(行 r, 列 c, 数字 n)` 映射为一条精确覆盖行，共 9×9×9 = 729 行，行号 `(r*9+c)*9+(n-1)`。每行覆盖 4 个约束列，共 324 列：

| 列区间 | 含义 | 列号 |
|---|---|---|
| 0..80 | 本格占用 cell(r,c) | `r*9+c` |
| 81..161 | 行 r 内含数字 n | `81+r*9+(n-1)` |
| 162..242 | 列 c 内含数字 n | `162+c*9+(n-1)` |
| 243..323 | 宫 b 内含数字 n | `243+b*9+(n-1)` |

求解用 Algorithm X 思路：每步选择**候选数最少的未覆盖列**（平局取列号最小者），按 r、c、n 升序尝试候选行；选中即覆盖其 4 列并禁用冲突行，撤回时用引用计数精确恢复（一行可能被多个已覆盖列同时禁用，计数归零才恢复）。候选与列的平局顺序完全固定，重复执行得到相同首批结果。未使用 Dancing Links 指针优化，也未调用任何现成数独/SAT/约束求解器。

## 唯一性判断与预算口径

- **节点计数口径**：每"选中一个约束列并尝试一个候选行"计 1 个节点（`nodesVisited`）；`backtracks` 为撤回落子的次数。
- 搜索最多保留 **2 份**不同解。找到 1 份不能立即称唯一——只有**穷尽全部剩余分支且恰好 1 解**才判定 `unique`；找到 2 份即判定 `multiple`（至少两解）；穷尽且 0 解判定 `none`。
- 节点预算耗尽时返回 `exhausted`：保留已找到的解，但结论为**未知**，绝不冒充无解或唯一。
- 预算范围 `1..10000000`，默认 `1000000`。

## 独立答案核验

`verifySolution` 不依赖精确覆盖搜索的任何成功标志，直接检查：81 格形状、取值范围、缺格、每行/每列/每宫各含 1..9、原线索未被改写。外部答案缺格、重复数字或篡改线索时返回具体失败位置（`kind` + 坐标）。求解器输出的每份解在入库前也必须通过该独立核验；多解结果附带两份均通过核验的见证。

## HTTP API

默认端口 0（自动选空闲端口），可用 `--port` 或环境变量 `PORT` 指定。数据保存在项目内 `data/sudoku.db`（可用环境变量 `SUDOKU_DB` 覆盖）。

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/puzzles` | 导入题面 `{givens, budget?}`，创建题目与版本 1 |
| PUT | `/api/puzzles/:id` | 更改线索，**新建版本**（旧版本与其结果保留） |
| POST | `/api/versions/:versionId/solve` | 求解 `{budget?}`，结果落库 |
| POST | `/api/solve` | 免持久化直接求解 |
| GET | `/api/puzzles/:id` | 查看题目、全部版本及各版本结果 |
| GET | `/api/results/:id` | 查看结果（解、节点数、回溯数、停止原因） |
| GET | `/api/results/:id/steps?offset=&limit=` | 分页查看搜索步骤（limit ≤ 500） |
| GET | `/api/results/:id/export` | 导出完整结果（含全部步骤与版本信息） |
| POST | `/api/verify` | 独立核验外部答案 `{givens, solution}` |

### 错误码

| 错误码 | HTTP | 含义 |
|---|---|---|
| `INVALID_FORMAT` | 400 | 题面非 81 格或含非法字符 |
| `INVALID_JSON` | 400 | 请求体不是合法 JSON |
| `BUDGET_RANGE` | 400 | 预算超出 1..10000000 |
| `DIRECT_CONFLICT` | 409 | 行/列/宫直接重复，`details` 含冲突坐标 |
| `NOT_FOUND` | 404 | 题目/版本/结果不存在 |
| `INTERNAL` | 500 | 内部错误（含求解器输出未通过独立核验） |

所有写库操作使用事务，输入或保存失败不会留下半份成功结果。SQLite 保存题面版本、预算、算法口径（`exact-cover-algorithm-x-v1`）与结果，重启后仍能读取原解与原限制；不持久化回溯栈，重新发起求解会生成新报告。

## 搜索步骤记录

每份结果附带受限搜索步骤（默认最多 10000 条，超出标记 `stepsTruncated`），每条记录：深度、所选约束列（类型/描述/当时候选数）、选中候选 `(行,列,数字)`、该列可选候选数。**这是搜索记录而非必然逻辑提示**——记录的是回溯搜索的猜测与撤销，不代表人类式推理。

## 测试

`npm test` 覆盖：完整合法盘、仅缺一格、宫内冲突、篡改原线索、直接冲突坐标、无直接重复但无解、空盘多解双见证、极小预算耗尽、重复求解确定性、步骤分页、失败路径（错误码）、重启后读取原解与原限制，并用独立朴素逐格回溯计数器对接近完成的少量空格盘计数到两解、与正式分类交叉对照。

## 已知限制

- 仅经典规则，无难度评分、题目生成。
- `node:sqlite` 在 Node 25 仍带 ExperimentalWarning，不影响功能。
- 步骤记录上限 10000 条，超长搜索只能看到前缀。
- 空棋盘等超大解空间题目在默认预算内只能给出"至少两解"，不会枚举全部解。
