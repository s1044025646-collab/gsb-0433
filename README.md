# 九宫数独精确覆盖求解与唯一性核验后端

纯后端项目（API + CLI），TypeScript + Node.js + SQLite（`node:sqlite` 内置模块，无原生编译依赖）。
只做经典 9x9 数独：每格 1-9，每行、每列、每个 3x3 宫恰好含 1-9。不含对角线、杀手笼、难度评分、题目生成与联网题库。

## 运行环境

- Windows 本地，Node.js >= 22.5（开发使用 Node 25 验证），无需 Docker / WSL / 外部服务。

## 常用命令

```powershell
npm install        # 安装 devDependencies（typescript、@types/node）
npm run build      # 编译 src -> dist，测试 -> dist-test
npm test           # 构建并运行全部测试（node:test）
npm start          # 启动 API 服务（默认端口 0 = 自动选择空闲端口，PORT 环境变量可指定）
npm run cli -- solve <81位数字|文件> [--budget N]
npm run cli -- verify <题面> <答案>
npm run demo       # 五个内置演示：唯一解 / 直接冲突 / 无重复但无解 / 空棋盘多解 / 极小预算
```

数据目录为项目内 `data/`（可用环境变量 `SUDOKU_DB` 指定数据库文件路径）。

## 精确覆盖映射

每个候选落子 `(行 r, 列 c, 数字 n)`（r,c 0-8，n 1-9）生成一行，共 729 行。
每行覆盖 4 个约束列，共 324 列：

| 列区间  | 含义                     |
|---------|--------------------------|
| 0-80    | 格 (r,c) 必须被占用      |
| 81-161  | 第 r 行必须含数字 n      |
| 162-242 | 第 c 列必须含数字 n      |
| 243-323 | 第 b 宫必须含数字 n      |

求解为 Algorithm X 的确定性回溯：每步选择**当前可选候选数最少的未覆盖列**（平局取列号最小），
候选按 `(r,c,n)` 字典序固定尝试。选中候选即停用所有冲突行并覆盖对应列，撤回时通过撤销栈精确恢复。
使用数组 + Set 实现，未使用 Dancing Links 指针，也未调用任何现成数独 / SAT / 约束求解器。

## 计数口径与唯一性判断

- **访问节点数**：每次"选中一个候选行并递归进入搜索"计 1（线索预覆盖不计）。
- **回溯数**：候选递归返回且未产生新解的撤销次数。
- **唯一解**：找到一份解后**继续穷尽剩余全部分支**，恰好一份才报告 `unique`。
- **至少两解**：找到两份不同解即报告 `multiple`（最多保留 2 份见证，其余分支不再穷尽）。
- **无解**：穷尽全部分支无任何解，报告 `none`。
- **预算耗尽**：节点数达到预算（默认 100000，可配 1..10,000,000）报告 `budget_exhausted`，
  保留已找到的解并明确标注"搜索空间未穷尽，结论未知"，绝不冒充无解或唯一。
- 重复执行同一题面与预算，节点数、首批解与搜索步骤完全一致（确定性）。

## 独立答案核验

`verifySolution` 不依赖精确覆盖搜索的任何标志，直接检查：81 格填满、每行/每列/每宫无重复、
原线索未被改写。失败时给出具体位置与错误类型：
`MISSING_CELL`（缺格）、`ROW_DUP` / `COL_DUP` / `BOX_DUP`（重复）、`CLUE_CHANGED`（篡改线索）、`INVALID_FORMAT`。

## 线索校验

求解前先检查格式与行/列/宫直接重复；发现冲突返回 `CLUE_CONFLICT` 及冲突坐标，不进入搜索。
无直接重复但不可完成的题才报告 `none`。

## API 一览

所有响应为 JSON；错误结构为 `{ "error": { "code", "message", "details?" } }`。

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/validate` | 校验线索 `{givens}` |
| POST | `/api/puzzles` | 导入题面（创建首个版本） |
| POST | `/api/puzzles/:id/versions` | 修改线索，新建版本 |
| GET  | `/api/puzzles/:id` | 查看题面与全部版本 |
| POST | `/api/versions/:id/solve` | 求解 `{budget?}`，保存结果 |
| GET  | `/api/versions/:id/results` | 该版本全部求解记录 |
| GET  | `/api/results/:id` | 查看结果（状态、节点、回溯、停止原因、解） |
| GET  | `/api/results/:id/steps?page=1&pageSize=100` | 分页查看搜索步骤 |
| POST | `/api/results/:id/verify` | 核验外部答案 `{solution}` |
| GET  | `/api/results/:id/export` | 导出完整 JSON（题面、预算、算法、解、步骤） |

错误码：`INVALID_FORMAT`（400）、`INVALID_PARAM`（400）、`CLUE_CONFLICT`（422）、`NOT_FOUND`（404）、`INTERNAL`（500）。

`givens` / `solution` 接受 81 个 `0-9`/`.` 字符（0 或点为空格），或 9 行各 9 字符。
`budget` 为 1..10,000,000 整数，默认 100000。步骤分页 `page>=1`，`pageSize` 1..1000。

## 持久化

SQLite 三张表：`puzzles`、`puzzle_versions`（每次修改线索产生新版本，旧版本与旧结果保留）、
`results`（保存预算、算法标识 `exact-cover-algorithm-x-v1`、状态、节点/回溯数、停止原因、解与搜索步骤）。
重启后原解与原限制仍可读取（测试已覆盖）。不持久化回溯栈、不支持自动续算，重新求解生成新报告。
保存失败不会留下半份结果（导入失败即回滚已建题面）。

搜索步骤是**搜索记录**（每次选择的约束列与候选及其结果），不是逻辑提示，不把猜测冒充必然推理。

## 测试

`npm test` 共 13 项，覆盖：解析、直接冲突坐标、唯一解、无直接重复但无解、空棋盘多解（两份见证均过独立核验）、
极小预算未知、重复求解稳定性、完整合法盘、缺一格、宫内冲突（不同行列）、篡改线索，
以及用独立朴素逐格回溯对接近完成的少量空格盘计数到 2 并与正式分类对照；API 全流程含失败路径与重启读取。

## 已知限制

- 仅经典规则；搜索步骤记录上限 10000 条（超出置 `traceTruncated`）。
- 空棋盘等多解题只保留前 2 份见证。
- 单进程服务，无鉴权，面向本地使用。
